3. 必须整改的问题

P1-01 · Forward 基准没有测到待验收的 Triton 实现

benchmark/scripts/benchmark_embedding.py:50 为 Liger 模块设置 _benchmark_kernel_operation_mode。src/liger_kernel/transformers/experimental/embedding.py:22–25 在 NPU 且为 forward 模式或关闭梯度时调用 torch.nn.functional.embedding。基准辅助代码 benchmark/scripts/utils.py:162–163 还使用 torch.no_grad()，因此仅删除模式标记仍不足以恢复自研 Forward 测量。

if self.weight.device.type == "npu" and (
    not torch.is_grad_enabled()
    or getattr(self, "_benchmark_kernel_operation_mode", None) == "forward"
):
    embedded = torch.nn.functional.embedding(indices, self.weight)
else:
    embedded = LigerEmbeddingFunction.apply(self.weight, indices)

在 NPU 上以临时进程加载当前封装源码并对 functional.embedding 计数，实测：forward flag native calls 1、no_grad native calls 1。探针通过 runpy 直接加载封装文件，未替换其实现；不是完整安装后的 pytest 通过证明。

影响：现有 Forward Torch/Liger 接近的结果可能是原生实现之间的比较，不能归因为 Tile、M5 或 core multiplier 优化。与 FINAL 报告“Forward 不再回退原生 embedding”的声明直接冲突。整改必须恢复正常推理及标准基准走待验收 kernel，并通过实际 kernel 名或调用链证据确认。

P1-02 · 当前环境无法复现全量测试与 Benchmark

本轮实测版本为 torch=2.7.1、torch-npu=2.7.1.post8、triton-ascend=3.2.2，未满足任务指定 torch_npu 2.9.0。源码 pyproject.toml 声明 0.8.2 不等同于包已正确安装。

pytest -q test/transformers/test_embedding.py
→ ImportError while loading conftest
→ ModuleNotFoundError: No module named 'transformers'

PYTHONPATH=src python benchmark/scripts/benchmark_embedding.py
→ AttributeError: module 'torch.cpu' has no attribute 'empty_cache'

已定位因果链：src/liger_kernel/utils.py:60–67 依赖 transformers.utils 检测 NPU，导入异常后返回 False；因此即使先导入 torch_npu，infer_device() 仍返回 cpu，自动导入通用 embedding。强制 LIGER_KERNEL_IMPL=ascend 又因当前设备被识别为 cpu 报错。直接创建 NPU tensor 的探针可以运行，不能把问题误判为“服务器没有 NPU”。

整改：按任务版本准备并记录完整环境、安装工程依赖，验证 infer_device()==npu、函数模块为 Ascend 实现，然后以不修改断言和容差的测试文件重跑。测试目录与 Issue 中 tests/test_embedding.py 不同，应提交路径映射及上游版本依据。

P1-03 · 当前性能证据无法支撑验收

当前 benchmark/data/all_benchmark_data.csv 经 csv.DictReader 检查，有 144 条 embedding 记录，全部标为 NVIDIA A100-SXM4-80GB / 2024-09-03；对应 liger、huggingface、torch_compile 的 forward speed、full speed、full memory，各组合 16 条，未见 Ascend embedding 或 backward 数据。这与性能报告所称 2026-10-05 Ascend CSV 不一致。

项目文件检索未找到报告引用的 BENCH_M5_RAW.txt、FINAL_BENCHMARK_RAW.txt、其他 FINAL_*_RAW、PYTORCH_COMPARISON_REPORT.md、ENVIRONMENT_REPORT.md、PROFILING_BASELINE_COMPARISON_REPORT.md；明确检查 profiling/、BENCH_M5_RAW.txt、FINAL_BENCHMARK_RAW.txt 返回不存在。结论限定为“当前提供的工程中未找到”，不排除这些材料保存在其他历史环境。

整改：为同一提交、同一设备、同一环境、同一配置矩阵重新生成优化前后原始结果、比值表和命令日志。每行至少包含 mode、shape、D、V、dtype、padding、provider、P50、单位、硬件、提交和时间。必须保留不达标行，不得以均值加速或其他模式收益抵消单配置回退。

P1-04 · 非连续索引输入发生布局兼容性回归

src/liger_kernel/ops/backends/_ascend/ops/embedding.py:354–356 在前向去掉连续化后直接执行 indices.view(-1)。本轮使用合法索引 torch.arange(6, device='npu').reshape(2,3).t()，权重为 8×4，直接调用该 Ascend 前向函数，实测：

RuntimeError: view size is not compatible with input tensor's size and stride
(at least one dimension spans across two contiguous subspaces).
Use .reshape(...) instead.

影响：转置二维索引无法进入计算；不能以只覆盖连续一维输入的 11 个历史用例证明 shape / 布局泛化已完成。该发现是布局问题，不表示所有二维输入都失败。整改后需覆盖非连续索引、连续多维、标量、空输入、INT/LONG，并验证输出 shape 与参考一致；非连续 weight 的处理也应核查。

P2-05 · 精度覆盖、Profiling 与交付材料不足

测试 test/transformers/test_embedding.py:34 仅配置 FP32（atol=1e-6、rtol=1e-5）；第 46/49 行生成一维 320 个 token。第 54/61 行分别检查前向和权重梯度，已有基本正确性测试，但缺 FP16/BF16、宽 hidden size 与布局泛化的验收证据。相对初始化提交 c5983e6，测试只移除了 skip，未改断言与容差；不能把覆盖不足描述成故意放宽精度。

Profiling 报告实际描述 D=2048、BT=4096、M6 的旧版本，仅有两条主机/设备时间记录，并明确承认缺基线 profile 和 PMU 指标。不能据此确认最终 D=4096、BT=8192、M5 配置的带宽、指令或调度根因。FINAL 报告还称 Backward 宽 hidden 使用 core multiplier 8，而当前第 413 行实际按 token 区间选择 1 或 2。策略报告“10 组通过”与最终报告“11/12”也应统一。

整改需补 FP16/BF16 数值与梯度、重复索引、padding 边界测试，保留原有断言与容差；采集同配置 baseline / candidate 的原始 profile，解释 kernel 次数、host/device 时间、非融合路径和具体优化收益。涉及带宽、UB/register 压力或指令瓶颈的结论，应补相应计数器证据，或明确标为假设。A2/A3/950 的验证与硬件限制说明仍需补齐。
